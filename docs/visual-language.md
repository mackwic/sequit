# Langage du document, du layout et des assertions visuelles

## Document de travail

Version de travail du 9 septembre 2026, à compléter, corriger et valider. Ce document inventorie le vocabulaire utile pour parler du layout de Sequit, puis écrire des assertions et des tests de propriétés. Il part des atomes et va vers les compositions.

Le périmètre couvre le document, la géométrie, le routage, la disposition, le rendu et leur vérification. Il ne vise pas un glossaire complet de la collaboration, de l'édition ou du design graphique.

**Les entrées validées et les décisions ci-dessous consignent le langage et les intentions retenus. Elles ne prouvent pas que les règles de placement correspondantes sont implémentées.** Un terme utile ne nécessite pas forcément une classe : il peut désigner une donnée, une sélection, une mesure ou un prédicat.

Le glossaire est le support écrit du langage partagé. Les termes retenus pourront être employés de façon cohérente dans les discussions, le code et les tests.

Page locale : `/atelier/lexique`. Les sauvegardes de la page modifient ce fichier. Les identifiants `VL-…` servent de références stables pour la discussion ; conserver ces identifiants lors des corrections.

### Comment réviser

- Ouvrir `/atelier/lexique` avec le serveur de développement pour éditer les termes FR/EN, les définitions, les remarques et les décisions.
- Cliquer sur « Enregistrer les modifications » pour écrire dans ce fichier. La sauvegarde est locale et explicite ; un conflit est signalé si le fichier a changé depuis son chargement.
- Chaque terme possède un lien direct, par exemple `/atelier/lexique#VL-302` pour la boîte.
- Les remarques sont des notes partagées via ce fichier, sans synchronisation temps réel.
- Le bouton « Exporter le brouillon » permet de conserver les modifications sans écraser le fichier.
- « Ajouter un terme » crée une entrée FR/EN dans la famille choisie ; « Retirer ce terme » la retire du brouillon. Le dernier retrait peut être annulé, et les changements sont appliqués au fichier à l’enregistrement.
- Le fichier reste directement éditable pour revoir les exemples ou compléter les sections libres.
- Renseigner la colonne « Décision » : `todo` (à examiner), `to update` (à modifier), `ok` (validé), `???` (joker, à voir plus tard).
- Utiliser les espaces de notes pour ajouter des exemples, exceptions et termes manquants.
- Un terme marqué « existant » existe dans le code ou la documentation ; sa définition proposée ici reste à valider.
- Les noms anglais sont des candidats pour le code, pas une obligation de renommer l'existant.

### Illustration de vocabulaire, sans règle imposée

```text
     [A]             [B]
      │               │    branches
      └───────┬───────┘    traverse commune
              │            tronc commun
              ▼            pointe de flèche
             [C]
```

Ce dessin représente deux relations arrivant sur C. Le raccord en T n’est pas une jonction XOR. Le partage de la traverse et du tronc est souhaitable ici parce que les deux relations ont la même destination C.

## 9. Application aux deux exemples discutés

### Exemple 1 : les flèches horizontales sur un même plan

Reformulation candidate : les tronçons transverses des relations entrant dans la jonction logique partagent une droite support et forment une traverse commune connectée.

- « Sur le même plan » devient ici « sur la même droite horizontale » pour un layout vertical.
- Une source située dans l'axe de la cible peut avoir une route droite sans tronçon horizontal de longueur positive.
- La traverse doit se situer hors des boîtes, avec le dégagement retenu.
- La présence d'une jonction XOR ne suffit pas à définir les règles de placement de ses sources.

Décision / reformulation :

> À compléter.

### Exemple 2 : le nœud d'arrivée centré sous deux sources

Reformulation candidate : l'axe central vertical de la boîte cible coïncide avec celui de l'enveloppe des deux boîtes sources.

- Le mot « parent » de la discussion désigne ici la cible commune ; il ne présume pas une relation parent-enfant dans un arbre.
- Les deux boîtes sources constituent ici un ensemble considéré pour la mesure. Le mot « groupe » est réservé à un groupement explicite du document.
- Le centre retenu est celui de l’enveloppe des boîtes sources, conformément à VL-310.
- Si B est aussi rattaché à D, B et ses descendants peuvent se déplacer. Le centrage de C peut alors être recalculé sur l’enveloppe des positions courantes de A et B. L’évitement des croisements prime sur le centrage exact ; l’arbitrage entre les autres contraintes concurrentes reste à préciser.

Décision / reformulation :

> Le centre de référence est celui de l’enveloppe des antécédents directs. Un ajout de relation autorise leur déplacement, celui de leurs descendants et le recentrage de la cible ; il n’impose pas le déplacement de tous les descendants.

### Exemples de centrages concurrents précisés par les dessins

Les deux exemples fournis sont orientés bas-haut. Ils précisent les placements attendus dans ces cas. Le dessin corrigé confirme des routes suivant les axes avec des coudes arrondis ; les diagonales initiales étaient une simplification.

- **Deux cibles avec les mêmes antécédents** : A → C, A → D, B → C et B → D. A et B sont sur une rangée, C et D sur la suivante. C est aligné sur le centre de A, D sur celui de B. Les deux cibles ne sont pas chacune centrées sur l’enveloppe de A et B. Le dessin montre un croisement entre les deux relations diagonales ; dans le rendu, tout croisement sans raccord doit recevoir le pont déjà décidé. Cet exemple ne supprime pas la préférence générale pour l’évitement des croisements.
- **Deux cibles larges avec un antécédent partagé** : A → D, B → D, B → E et C → E. A, B et C occupent une rangée, D et E la suivante. D est aligné sur le centre de A, E sur celui de C ; B reste entre A et C et rejoint les deux cibles. D et E restent espacés malgré leur largeur. Ce placement n’exige pas de centrer individuellement D sous A–B et E sous B–C.

Ces exemples valident des alignements de centres entre nœuds de rangées successives, au prix du centrage exact de chaque cible sur l’ensemble de ses antécédents. Ils ne définissent pas encore l’arbitrage pour tous les graphes ou toutes les tailles de boîtes.

## 10. Décisions du 11 septembre 2026 et points à préciser

Décisions retenues :

- [x] Le layout possède un axe principal, une direction et un biais le long de cet axe.
- [x] Une rangée est perpendiculaire à l’axe principal.
- [x] Nœud : objet logique ; boîte : représentation visuelle ; carte : terme écarté.
- [x] Jonction : objet logique ; raccord graphique : réunion de tracés.
- [x] Un groupe est toujours un groupement explicite du document.
- [x] Relation : lien logique ; route : géométrie calculée ; chemin rendu : tracé affiché ; flèche : représentation avec indication du sens.
- [x] Le partage d’une traverse ou d’un tronc est autorisé et souhaitable pour une même source ou une même destination. Des destinations différentes n’interdisent pas un tronc de sortie lorsque la source est commune. Des relations sans source ni destination commune doivent rester distinctes.
- [x] Le centre d’un ensemble est le centre de son enveloppe.
- [x] La référence usuelle des mesures est le rectangle, avec un dégagement de sûreté adapté à la mesure ; l’espacement se mesure entre bords.

L’usage principal est de présenter ou d’inspecter un raisonnement à l’écran ou sur papier. Rechercher une densité lisible, sans excès ; accepter un graphe plus étalé lorsque cela permet de supprimer un croisement. Les ombres et animations sont secondaires dans les conventions de mesure.

Compléments retenus :

- [x] Le tronc commun de sortie de J2 vers D et E est intentionnel : les relations partagent leur source. Cette autorisation vaut pour une source commune, pas seulement pour les jonctions.

- [x] Une jonction peut avoir deux sorties. Le dessin fourni représente A et B vers J1, J1 vers C, C vers J2, puis J2 vers D et E. Il valide cette topologie ; les libellés AND du dessin ne sont pas une preuve de prise en charge de cet opérateur dans le code.

- [x] Routage orthogonal avec possibilité de coudes arrondis au rendu, conformément au dessin corrigé. Les diagonales des premiers exemples ne sont pas une intention de routage.
- [x] Ajuster les réglages visuels dans le workbench : espacements, dégagements, décalages des chemins, dimensions des ponts, arrondis et nuances.

- [x] Le biais est par défaut du côté de l’origine de la direction et peut être remplacé dans la configuration du layout. Pour A → B → C et A → D en haut-bas, D partage la rangée de B avec un biais haut, celle de C avec un biais bas. Le rang logique et la rangée de placement doivent être distingués.
- [x] Une relation vers un groupe s’arrête au contour du groupe ; elle ne se prolonge pas jusqu’à ses membres.

- [x] À chaque croisement sans raccord intentionnel, rendre un pont de franchissement systématique, y compris sur papier. Lorsque des chemins doivent rester distincts, ne pas leur donner un tronc commun : décaler légèrement les portions susceptibles de se confondre. Rechercher en complément une légère différence de teinte, par exemple entre nuances de noir. La teinte est un indice supplémentaire, jamais un remplacement du décalage ou du pont. Le partage intentionnel entre relations de même source ou de même destination reste régi par VL-412 et VL-413.

- [x] L’évitement des croisements prime sur le centrage exact et sur la compacité. Décentrer une cible ou étaler davantage le graphe est préférable si cela permet de supprimer un croisement.

- [x] Réordonner les nœuds pour éviter les croisements lorsque c’est possible. Pour A → D et B → C entre deux rangées de deux nœuds, préférer réordonner la seconde rangée pour aligner les nœuds reliés plutôt que conserver un ordre créant un croisement. Cette préférence ne garantit pas l’absence de croisements dans tous les graphes.

- [x] Pour l’alignement entre rangs successifs, privilégier les centres des nœuds, particulièrement lorsque les deux rangs ont le même effectif. Cette préférence esthétique est compatible avec des espacements mesurés entre bords.

- [x] Les jonctions ne participent pas au calcul des rangs des nœuds. Leurs rangées visuelles s’intercalent dans l’espace entre les rangées de nœuds, perpendiculairement à l’axe principal, sans créer un rang logique supplémentaire.

- [x] Rang : retenir le plus long chemin indépendamment du biais. Pour A → B → C et A → C, les rangs des nœuds sont 0, 1, 2. Les relations entre nœuds progressent dans la direction du layout ; les raisonnements circulaires sont hors scope. Cela n’interdit pas les tronçons transverses d’une route.
- [x] Recalcul du centrage : si B pointe aussi vers D, B peut se déplacer, ses descendants peuvent également se déplacer et C peut être recentré sur l’enveloppe courante de ses antécédents A et B. Ce déplacement des descendants est autorisé, pas obligatoire.
      Points à préciser :

- [ ] Si plusieurs centrages restent incompatibles après prise en compte des croisements, leur arbitrage reste à définir.
- [ ] Ajuster dans le workbench les valeurs des réglages visuels et préciser les tolérances des tests correspondants.

## 12. Passage futur vers le code

Une fois le vocabulaire validé, une API pourra s'appuyer sur les types et le harnais existants. Exemples de formulation uniquement :

```ts
assert(boxA, boxB).areAligned({ by: 'top' });
assert(target, sources.envelope()).areAligned({ by: 'centerX' });
assert(segmentA, segmentB).areCollinear();
```

Ces appels ne sont pas implémentés. Le choix classe/module, les sélecteurs, la représentation des diagnostics et l'intégration navigateur restent ouverts. Les mêmes prédicats pourront servir aux exemples fixes et aux propriétés générées, sans intégrer le PBT à leur définition.
